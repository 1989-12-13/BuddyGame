# 界面收敛记录（2026-09-15）

本轮处理试玩后集中反馈的七项界面问题。原则：**能删的删掉，不能删的收敛到一处，不要让玩家找按钮。**

## 节点 1：桌面三栏常驻 —— ⛔ 已回退，按 origin/master

- 本地曾把「三栏 → 单视图」收进 `@media (max-width:1279px)`，让 ≥1280px 三栏常驻。
- 合并 origin/master 后决定：**主界面与操作台以远端为准**，这一条连同下面的操作条一起回退。
- `WorkbenchScreen.tsx` / `workbench.css` 现直接用远端版本，只保留删改道这一处小改动。

## 节点 2：操作条常驻底部 —— ⛔ 已回退，按 origin/master

- 远端把线路 chips 并进了顶部 chip 行、移除了工作区大标题，并把 `NextStepDock` 留在工作区顶部。
- 派车入口回到远端的组织方式；本地不再额外加底部 `.action-bar`，也不重复放置「结束当前通话」。

### 保留下来的一点

- 远端这版 `WorkbenchScreen.tsx` 仍然引用已删除的改道（面板与状态），已在上面按「删改道」处理干净：
  移除 `ReroutePanel` 引用、`centerBusy` / `workspaceDemand` 里的 `pendingReroute`、以及 `DISPATCH` 的 `routeOptions`。

## 节点 3：登记表退成只读摘要

- 玩家早已不用手工填表：问询与判断会自动写入 `terminal`。表单留着只会让人以为「还有东西没填」。
- `TaskCard` 改为：默认显示四项关键字段（地点 / 意识 / 呼吸 / 判定码）+ 完成度；「展开完整登记表」按需展开原表单（仍可微调）。
- 删掉任务卡底部的移动端派车按钮。

## 节点 4：删除途中改道

- 反馈：功能不完善（选项与 ETA 对比都不到位），且在并发下会打断正在处理的另一通电话。
- 删除范围：`pendingReroute` / `rerouteOptions` / `rerouteUsed` 三个状态字段、`ReroutePrompt` 类型、`REROUTE_AMBULANCE` action、`reducers/reroute.ts`、`ReroutePanel.tsx`、相关 CSS 与测试；`handleDispatch` 不再接收 `routeOptions`。
- 保留的部分：路况变化仍然发生，仍然写入对话流并调整 `etaTotal`——只是不再要求玩家二次决策。
- `lineNeedsDecision` 改为基于「第二位来电者的信息冲突未处置」，语义仍然成立。

## 节点 5：拿掉暴露内部数值与冗余提示

- 状态条删掉「已完成 X / 6 通」：它把班次的硬上限摊给玩家，容易变成「盯着计数器打」，也和「班次长度由热度决定」的设计叙事冲突。
- 对话抽屉删掉标题「下一句，你说什么？」：选项按钮本身已经说明一切，标题只是重复。
- 收班叙事 `collapse` 由两句缩为一句（保留「先下来，喝口水」）。

## 节点 6：首次值班引导

- 新增 `OnboardingCoach`：四步跟着做——接听线路 → 挑一句说 → 在「下一步」派车 → 等车期间保持通话。
- 回退到远端界面后，第三步的锚点从已移除的 `.action-bar` 改为远端仍在的 `.next-step`。
- 每一步圈住真实控件，做到了（`done()`）自动进入下一步；目标还没出现就等它出现；卡片之外不拦点击，响铃了照样能接。
- 完成后写 `dispatch120-onboarded`，此后不再出现；随时可跳过。

## 节点 7：同步修正对外材料

- `slides/index.html` 三处已不成立的表述已更新：
  1. 班次长度 —— 改为「上限 6 通 + 热度决定实际打几通」（原写「代码里没有任何一处写着今晚几通」，与 `targetCalls: 6` 矛盾）；
  2. 在途事件 —— 改道改为「路况只改 ETA，不再中途打断」；
  3. 响应式与测试数字 —— 改为 38 文件 / 1198 用例（断点回归远端方案，已从稿中撤下「两档断点」那条）。

## 节点 8：左右抽屉（地图 / 登记表）+ 中间通话居中

用户要求：删掉「下一步」那一整块、地图挪到左边并默认隐藏、登记表挪到右边，
两者以梯形把手对称开合，中间留给通话。

- **移除「下一步」整块**：`NextStepDock` 组件改为 `DispatchAction`，只保留一个动作按钮，
  去掉「下一步」标题与「3 / 4 已确认」——完成度读数本来就在通话台顶部（`NextStepChecks`），
  不重复第二份。相关 CSS（`.next-step` / `.next-step-head` / `.next-step-count`）一并删除。
- **左抽屉（地图 / 派车 / 指导 / 交接）**：`workspace-panel` 放到 `desk-grid` 第一列，
  ≥1280px 时列宽为 `0`，`overflow:visible` 让把手露在外面。
- **右抽屉（调度登记表）**：`task-panel` 放到第三列，同样收成 0。
- **梯形把手**：`.drawer-handle` 绝对定位在抽屉内侧边缘（左抽屉 `left:100%`、右抽屉 `right:100%`），
  垂直居中——收起时正好出现在屏幕中左 / 中右；用 `clip-path` 裁成梯形。窄屏隐藏，仍走标签页。
- **自动展开**：`mapDemand = plan || 问答结束 || 已派车 || 指导中 || 交接`，
  满足即拉开左抽屉，条件消失自动收回（沿用原先的 `hadDemand` 模式）。
- **弹出时机修正**：原先用「四项齐备」（`dispatchReady`）触发，四项齐了就会弹，
  此时玩家可能还剩地标 / 联系电话没问完。改为 **`nextProtocolId(state) === null`** ——
  六步协议（地点 / 事件 / 年龄 / 体征 / 地标 / 电话）都问过一遍才算「问答结束」。
  等待期里想提前看地图，用中左的梯形把手手动开。
- **中间居中**：对话流滚动区限制 `max-width:820px` 并 `margin-inline:auto`。
- 帮助弹窗的说明文案同步改成「中间通话 / 左右抽屉」。
- 引导组件第三步锚点由 `.next-step` 改为 `.drawer-actions`。

## 节点 9：删除视图切换按钮

用户要求：顶部 chip 行里的「通话 / 工作区 / 任务卡」三个切换按钮删掉。

- `WorkbenchScreen` 里的 `tab` 状态与 `type Tab` 整体移除，`setTab(...)` 的五处调用一并清掉；
  `<main>` 不再带 `tab-*` 类名。
- chip 行只剩「线路 chips（居左）」与「结束当前通话（居右）」，`aria-label` 改为「线路与通话操作」。
- 中间是通话，地图与登记表由左右抽屉的梯形把手开合 —— 视图切换已经没有存在意义。
- 窄屏兜底：原先靠 `tab-call / tab-map / tab-task` 单视图切换，现在改为**三块竖排堆叠**
  （`.desk-grid` 变 `flex-direction:column` + `overflow-y:auto`，`.desk-panel{min-height:340px}`），
  删掉 `max-width:959px` 里的 `display:none` 与三个 `tab-*` 规则。
- 顺手改名：`NextStepDock.tsx` → `DispatchAction.tsx`（文件里已没有 `NextStepDock`，
  只导出 `DispatchAction` 与 `NextStepChecks`），更新 `WorkbenchScreen` / `Transcript` 两处 import。
