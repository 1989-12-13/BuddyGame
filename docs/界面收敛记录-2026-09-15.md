## 节点 10：修复「选关后电话不来」——接听入口的位置

用户反馈：场景选择里点进某一关，电话迟迟不来，怀疑是场景映射坏了。

- **先验证映射，结论是没有坏**：新增 `src/game/events/levelCatalog.test.ts`，
  对选关列表里**每一个**关卡遍历验证 id 唯一、能在场景表里查到、
  `START_SHIFT → scenarioQueue` 写对、`ANSWER_CALL` 后 `currentCall.id` 就是该关卡。
  全部通过 → 映射链路本身没问题。
- **真正的原因在上一次抽屉改动里**：`shift-welcome`（含「接听来电」按钮）
  跟着工作区一起被搬进了默认收起的左侧抽屉。单关模式下玩家点进关卡后看不到任何入口，
  表现就是「没有电话打进来」。
- **修法**：`shift-welcome` 挪回中间的对话台 —— `!call` 时中间栏显示欢迎页与「接听来电」，
  有来电时才切换到对话流；抽屉只在 `call` 存在时渲染派车入口与地图/指导/交接。
  按下「接听来电」不再依赖任何抽屉是否展开。
- 顺带把选关列表的派生逻辑抽到 `src/game/events/levelCatalog.ts`（`LEVEL_CATALOG`），
  `LevelSelectScreen` 改为直接消费它，测试校验同一份数据，避免两边漂移。

## 节点 11：修复「心肺复苏派不出车」

用户反馈：心脏骤停（心肺复苏）关卡存在派车派不出去的情况。

- **先用探针脚本复现**：从选关表逐关跑「接听 → 问完六步 → 答掉判断卡」，
  再检查 `dispatchEligibility` 与 `buildDispatchPlan`，全部关卡都通得过 —— 说明不是数据问题。
- **定位到真正的错配**：`DispatchAction` 的就绪判断只看「地点 / 意识 / 呼吸 / 判定码」四项
  （`nextStepChecks`），而真正执行派车的 `dispatchEligibility` 还要 **联系电话**、
  非忙碌、车辆可用、`callPhase` 正确。四项齐了按钮就亮，点下去 `buildDispatchPlan` 返回 null，
  `openRoute` 里的 `if (next)` 直接吃掉 —— **按钮点了没反应、也不报错**。
  心脏骤停最容易撞上：判定码由 `step2_event` 后的判断题早早补齐，而联系电话（`ask_contact`）
  是六步里的最后一个；来电者一慌，这个回答还常常不完整，要重问才填得上。
- **修法**：`DispatchAction` 改为只认 `dispatchEligibility`（与派车同一个函数，单一事实源）；
  不满足条件时按钮置灰，并把 `reasons` 逐条列在下面（失败原因本来就已经写好文案），
  另给一个「打开登记表核对」入口。这样玩家看到的是「确认联系电话」而不是一个死按钮。
- 新增 `src/screens/game/DispatchAction.test.tsx`：条件齐备可点、缺联系电话时置灰并列出原因、
  已派车后不再出现派车提示，三条用例锁住这个错配不再复发。

## 节点 12：可派车时直接摆出路线选择，去掉那个按钮

用户反馈：抽屉顶部那个「规划救援路线」按钮没必要，需要派车时直接显示路径选择。

- 新增纯函数 `shouldAutoPlan(state, planActive, autoPlannedFor)`（`dispatchPlanning.ts`）：
  条件齐备、本通没自动开过、还没有方案在展示、还没派过车 → true。
  判定复用 `dispatchEligibility`，与真正派车保持同一个事实源。
- `WorkbenchScreen` 用一个 `autoPlannedCall` ref 记录「这一通已经自动开过」：
  条件一满足就 `buildDispatchPlan` + `setPlan` + 拉开抽屉，路线选择直接出现在画布上。
  只尝试一次的原因：路线种子含派车时刻，逐秒重算会给出不断变化的方案。
- 玩家主动取消（`onCancel` → `setPlan(null)`）后，抽屉里会把按钮还给玩家
  （`{call && !plan && <DispatchAction/>}`），绝不反复弹回来。
- 条件没齐时不自动开 —— 仍然由 `DispatchAction` 置灰并列出「还差什么」。
- `dispatchPlanning.test.ts` 增加 4 条规则用例（可自动开 / 同通只开一次 / 已有方案或已派车不再开 / 缺联系电话不开）。
