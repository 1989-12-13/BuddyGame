# 界面收敛记录（2026-09-15）

本轮处理试玩后集中反馈的七项界面问题。原则：**能删的删掉，不能删的收敛到一处，不要让玩家找按钮。**

## 节点 1：桌面回到三栏常驻

- `workbench.css` 原来的「三栏 → 单视图」规则是无条件的，导致桌面端也只有一栏 + 三个标签页。派车要切到「工作区」、核对信息要切到「任务卡」，是「要上下滑动」的直接来源。
- 现在把单视图规则收进 `@media (max-width:1279px)`；≥1280px 三栏常驻，`.view-tabs` 隐藏。
- 定位：**桌面为主**。窄屏保留单视图 + 标签作为兜底，不再单独优化触屏体验。

## 节点 2：操作条常驻底部

- 工作区底部新增 `.action-bar`：`NextStepDock`（核对登记表 / 规划救援路线）+「结束当前通话」。
- 它不随主区滚动，也不在任务卡里。派车入口从「三处」（任务卡底部、工作区顶部、需要切 tab）收敛为一处。
- 「结束当前通话」从工作区标题栏移到操作条，与主操作同层。

## 节点 3：登记表退成只读摘要

- 玩家早已不用手工填表：问询与判断会自动写入 `terminal`。表单留着只会让人以为「还有东西没填」。
- `TaskCard` 改为：默认显示四项关键字段（地点 / 意识 / 呼吸 / 判定码）+ 完成度；「展开完整登记表」按需展开原表单（仍可微调）。
- 删掉任务卡底部的移动端派车按钮。

## 节点 4：删除途中改道

- 反馈：功能不完善（选项与 ETA 对比都不到位），且在并发下会打断正在处理的另一通电话。
- 删除范围：`pendingReroute` / `rerouteOptions` / `rerouteUsed` 三个状态字段、`ReroutePrompt` 类型、`REROUTE_AMBULANCE` action、`reducers/reroute.ts`、`ReroutePanel.tsx`、相关 CSS 与测试；`handleDispatch` 不再接收 `routeOptions`。
- 保留的部分：路况变化仍然发生，仍然写入对话流并调整 `etaTotal`——只是不再要求玩家二次决策。
- `lineNeedsDecision` 改为基于「第二位来电者的信息冲突未处置」，语义仍然成立。

## 节点 5：拿掉暴露内部数值与冗余提示

- 状态条删掉「已完成 X / 6 通」：它把班次的硬上限摊给玩家，容易变成「盯着计数器打」，也和「班次长度由热度决定」的设计叙事冲突。
- 对话抽屉删掉标题「下一句，你说什么？」：选项按钮本身已经说明一切，标题只是重复。
- 收班叙事 `collapse` 由两句缩为一句（保留「先下来，喝口水」）。

## 节点 6：首次值班引导

- 新增 `OnboardingCoach`：四步跟着做——接听线路 → 挑一句说 → 底部派车 → 等车期间保持通话。
- 每一步圈住真实控件，做到了（`done()`）自动进入下一步；目标还没出现就等它出现；卡片之外不拦点击，响铃了照样能接。
- 完成后写 `dispatch120-onboarded`，此后不再出现；随时可跳过。

## 节点 7：同步修正对外材料

- `slides/index.html` 三处已不成立的表述已更新：
  1. 班次长度 —— 改为「上限 6 通 + 热度决定实际打几通」（原写「代码里没有任何一处写着今晚几通」，与 `targetCalls: 6` 矛盾）；
  2. 在途事件 —— 改道改为「路况只改 ETA，不再中途打断」；
  3. 响应式与测试数字 —— 改为两档断点、38 文件 / 1192 用例。
