01我要解决的问题Why this project
公益科普流程训练

不是再讲一遍知识，
而是让人亲手走一遍流程

公众大多只知道「出事打 120」，却不知道电话接通之后，调度员要在几十秒里问出地址、意识、呼吸，并据此派车。这段流程有标准（MPDS 五步），但普通人没有可以练习的地方——真调度台不能拿来练手。

01常识缺口。大部分人不知道「接起电话后要回答什么」，更不知道先说地址、再说情况。
02练习缺口。标准流程写在规范里，却缺少一个能安全犯错、错了有反馈的模拟器。
03形式缺口。科普多为视频与图文，看完就忘；缺少「做一次」带来的记忆。
我们的做法

把 MPDS 五步（地址 / 情况 / 联系人 / 目的）做成系统骨架，自动推进顺序；把措辞、时机与取舍留给玩家。玩家不需要背流程，但每个选择都有后果。

  • —不做急救认证教材，任何内容不宣称「已获医学认证」。
  • —不做拟真到令人不适的画面，全部以文字与示意图呈现。

04情绪系统：压力决定信息质量Stress → fidelity
STRESS 0–1004 档

安抚不是装饰，是拿信息的唯一办法

来电者压力越高，回答越失真。想要准确地址，就得先把人稳住——这条因果链必须在数值上成立。

压力区间档位回答保真度可用信息
0 – 24镇定clear准确、完整
25 – 49紧张partial基本可用
50 – 74恐慌vague模糊、缺关键项
75 – 100失控vague跑题、自相矛盾
安抚曲线：修掉了一个数值崩塌
第 1 次20
第 2 次16
第 3 次12
第 4 次起8

旧实现是 20 / (1 + 次数)，第 3 次只剩 6.7，失控档（85）要压 20 次才回到准确区间——「安抚换信息」在数值上根本不成立。现在改为线性递减且保留下限 8。

09班次没有固定通数，由热度决定Heat model
HEAT 0–100PEAK 85FLOOR 12

上限 6 通，但没人告诉你「还差几通」

班次的上限是 6 通（targetCalls），但热度决定你实际打几通：打得好 → 冲进峰值段撑过 2 通即圆满交班；患者死亡或连续漏接 3 通 → 被换下来；热度跌破地板 → 平静收班。界面上不显示计数，玩家只会感到「今晚越来越忙」或「夜渐深了」。

热度曲线与收班点
四种收班，全部由表现驱动
收班触发含义
perfect热度冲到峰值段并撑过交班
collapse患者死亡 / 连续漏接被换下来
fade热度长期低迷且已处理足够通话平静收班
complete正常走完本班常规交班

必须有「圆满收班」：否则打得越好打得越久，还会诱使玩家故意打差一点好早点下班。

关于时长的诚实说明

目标体验约 5 分钟，是标定出来的结果，不是写死的输入。项目内 pacing.test.ts 的脚本模拟为 1133 秒——那验证的是连续完成与计时逻辑，不等于真实试玩时长。15 分钟真实体验仍需至少 5 名首次玩家验收。

口播：主动交代「5 分钟是标定值」，比被问出来好。

12四个关键决策，以及为什么Trade-offs
可复现可测试

踩过的坑，比功能的分量更重

每一条都对应一个曾经真实出错或即将出错的地方。

01 · 组合，而不是拆分

并发改造没有把 WorldState 拆散，而是让每条线路持有自包含的 WorldState，由班次层协调共享时钟、来电到达、聚焦与车辆。代价是状态体积更大，收益是既有 reducer 与全部单通测试一行未改。

02 · 成绩必须跨线路快照

线路会被复用，复用时 START_SHIFT 会重置该线路的评分与计时。直接读线路会丢掉前面所有成绩。现在在线路 active → done 的瞬间把成绩快照进班次层。

03 · 统一暂停，一套计时规则

暂停原因有五种（manual / background / settings / help / confirm）。嵌套弹窗下，关闭内层不得提前恢复外层冻结——世界、车辆、动作计时、小游戏与音频必须一起冻住。

04 · 确定性优先

定时事件按阈值跨越触发并按事件 ID 去重，问询事件使用明确问题 ID；测试用 Mulberry32 确定性 PRNG 复现场景。生产代码仍用 Math.random()，测试不依赖随机输出。

对照文件：src/game/core/shift.ts、session.ts、callEvents.ts、seededRandom.ts。
